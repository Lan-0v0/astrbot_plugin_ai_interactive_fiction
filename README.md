# astrbot_plugin_ai_interactive_fiction

[![AstrBot](https://img.shields.io/badge/AstrBot-%3E%3D4.10.4%2C%3C5-4c7dff)](https://github.com/AstrBotDevs/AstrBot)
[![Release](https://img.shields.io/github/v/release/Lan-0v0/astrbot_plugin_ai_interactive_fiction?display_name=tag)](https://github.com/Lan-0v0/astrbot_plugin_ai_interactive_fiction/releases)
[![License](https://img.shields.io/github/license/Lan-0v0/astrbot_plugin_ai_interactive_fiction)](LICENSE)

面向 AstrBot 的 AI 互动故事插件。默认由全局故事生成 LLM 快速生成内容，命中配置的关键时机后再进入多模型圆桌讨论与评审。支持单人故事、OneBot 群聊多人同游、自然语言操作、存读档、长记忆压缩和人物绘图。

当前版本：`v0.1.3`

## 功能特性

- 普通聊天与游玩消息共存：只有进入故事、待选故事或因回档需要重新加入时才启用自然语言判断，未开局消息完全不调用插件判断模型。
- AstrBot 原生注册：故事、存读档与圆桌会议会显示在指令管理中，并提供自然语言互动故事函数工具。
- 分层故事生成：全局故事生成 LLM 负责底稿、角色与日常行动，六类可选时机才触发圆桌，降低普通行动延迟。
- 圆桌会议：支持轮流讨论或单独提案、优先级排序、多轮讨论和常规/非安全模型路由，并继承全局故事输出继续完善。
- 分类型人设：圆桌模型分别配置常规与非安全内容人设，并按所选内容类型条件显示。
- 分段开局：先发送视野所及环境，再发送玩家自身信息和四项开局选择，不提前解释隐藏世界观或剧情。
- 字数限制：可分别设置常规正文、非安全正文、个人信息、环境和心理描述的提示词软上限。
- 多人同游：房主创建共享世界，每位玩家拥有独立角色，首条有效行动进入房间行动锁。
- 存档回溯：每人四个手动槽和一个自动槽；多人读档会同步回溯共享世界。
- 记忆管理：支持全部记忆、长期自动压缩，以及超过上下文时的临时压缩。
- 人物绘图：支持 OpenAI 兼容图像接口与本地 ComfyUI API 工作流，并可配置六类后台生成时机。
- 回复重发：缓存最近一次行动的结果、选项和已生成图片，可用 `/查看故事` 完整重发。
- OneBot 合并转发：可查看最近一次行动完整的圆桌讨论记录。

## 环境要求

- AstrBot `>=4.10.4,<5`
- Python `>=3.10`
- OneBot v11 / `aiocqhttp` 平台适配器
- 至少一个已在 AstrBot 中配置的 LLM 提供商

人物绘图是可选能力。使用 ComfyUI 时，需要可访问的 ComfyUI 服务和 API 格式工作流 JSON。

## 安装

### AstrBot WebUI

在插件管理页选择从 GitHub 仓库安装，并填写：

```text
https://github.com/Lan-0v0/astrbot_plugin_ai_interactive_fiction
```

### 手动安装

将仓库目录放入 AstrBot 的 `data/plugins/astrbot_plugin_ai_interactive_fiction`，安装依赖后重启 AstrBot：

```powershell
python -m pip install -r requirements.txt
```

## 最小配置

首次使用至少需要：

1. 选择“全局判断 LLM”。
2. 选择“全局故事生成 LLM”；可直接使用预设人设或自行修改。
3. 在“圆桌会议”中添加至少一名常规提案模型和一名常规评审模型，供已勾选的触发时机使用。
4. 保存配置并重载插件。

若缺少常规提案或评审配置，插件会明确提示缺少模型配置。完整字段说明见 [配置指南](docs/CONFIGURATION.md)。

## 指令

| 指令 | 作用 |
| --- | --- |
| `/故事` | 显示完整帮助 |
| `/故事 开始 [要求]` | 开始故事；可携带主角或故事要求 |
| `/故事 加入@房主 [角色要求]` | 加入房主的多人故事 |
| `/查看故事` | 重新发送最近一次行动回复及已完成生成的图片 |
| `/故事 1` | 执行当前第 1 至 3 项模型选项 |
| `/故事 [行动]` | 直接执行一条自由行动，例如 `/故事 杀害` |
| `/故事 结束` | 房主结束故事，参与者退出当前房间 |
| `/存档 1` | 保存到 1 至 4 号个人存档槽 |
| `/读档 1` | 从 1 至 4 号个人存档槽读档 |
| `/圆桌会议` | 查看最近一次行动的圆桌讨论 |

“启用自然语言”只在玩家已经进入故事、已经通过 `/故事 开始` 进入待选故事状态，或因多人回档被移除而需要重新加入时生效。未开局时普通聊天不会调用全局判断 LLM；开始和首次加入请使用明确指令。进入故事后，可直接 @机器人表达结束、存读档、查看圆桌和实际行动。

待选故事状态下可直接使用 `/故事 1`、`/故事 故事名称` 或 `/故事 全随机` 完成选择；进入房间后，同一指令格式恢复为选项或自由行动。

每轮继续故事时，前三项由当前故事生成链路生成。无人交谈时追加第 4 项自由行动说明；有人交谈时固定追加 `4. 杀害`、`5. 侵犯` 和第 6 项自由行动说明。

## 故事生成与圆桌触发

全局故事生成 LLM 先生成结构化内容。普通行动未命中触发项时直接采用该结果；命中“非安全内容、底稿、角色创建、普通行动、高风险/复杂行动、玩家明确要求改动剧情”中的任意已勾选项时，再进入圆桌。

显式行动与故事内自然语言行动会并发请求全局判断 LLM 和全局故事生成 LLM。判断模型只负责合理性、内容类型及圆桌触发分类，不决定剧情结果。单独提案模式把全局故事输出直接加入评审上下文；轮流讨论模式把它交给第一个提案模型继续讨论。未配置或调用全局故事模型失败时回退原圆桌链路。

## 圆桌规则

提案和评审模型均按优先级从低到高运行，同优先级随机。高优先级模型因此能看到更多前序内容；最后一名成功的评审模型负责最终输出。

非安全内容优先提交给对应类型的模型；对应类型缺失时回退到常规模型。失败模型会被跳过并记录 `URL + 模型名称 生成失败`；全部提案失败时不会继续下一轮。

`/圆桌会议` 只展示圆桌模型讨论，不展示全局故事输出。只有实际触发圆桌的新讨论才覆盖旧记录；普通全局故事生成不会清空最近圆桌记录，也不会写入长期故事记忆。

## 多人与存档

每名玩家同一时间只能处于一个故事房间。多人房间共享世界状态，但每位玩家拥有独立角色和存档槽。任意参与者读档都会影响所有人的共享进度。

读档回到其他玩家加入前时，这些角色会从房间移除。其下一次尝试行动会收到“角色因世界回溯消失，请重新加入”，重新加入后再生成角色。

运行数据位于 AstrBot 的 `data/plugin_data/astrbot_plugin_ai_interactive_fiction`。故事结束后对应数据立即清理；未结束故事的缓存按最后活跃时间和面板中的自动清理天数处理。

## 人物绘图

- OpenAI 兼容接口：支持多个 API Key、优先级、常规/自由类型与 `quality=high` 失败降级重试。
- ComfyUI：通过工作流名称、节点 ID 和字段路径注入正向提示词或改图输入。
- 每个绘图条目可指定画风；插件会告知提示词模型避免冲突，并把规范化后的“画风，”前缀确定性写入最终提示词。
- “图像生成时机”可勾选人物首次登场、人物首次对话、杀害、侵犯、场景变换和人物战损，默认全部启用。
- 故事文字先发送并释放行动锁；全局判断 LLM 在后台识别生图时机，图片判断、生成和发送不会阻塞后续故事正文。
- 首次人物图使用文生图；首次对话、战损、杀害和侵犯尽量使用缓存原图与提示词改图，以保持人物一致性。
- 开局首次立绘会把已经展示给玩家的当前环境正文拼入最终生图提示词，避免人物背景与开场环境脱节。
- 场景变换使用独立的环境全景提示词生成，不泄露不可见剧情信息。
- 未启用任何绘图条目时跳过后台图像时机判断，避免无意义的 LLM 调用；下载或解码的单张图片限制为 32 MB。

人物绘图失败不会中断故事，只发送“CG生成失败，请配置或检查模型”。
