# 配置指南

配置通过 AstrBot 内置插件配置面板管理。模型选择项引用 AstrBot 已配置的 LLM 提供商；插件不会要求在故事条目中重复填写聊天模型凭据。

## 全局设置

| 配置 | 说明 |
| --- | --- |
| 启用自然语言 | 仅在玩家已进入故事、待选故事或因回档需要重新加入时启用判断；未开局消息始终跳过插件 LLM |
| 全局判断 LLM | 负责消息意图、行动合理性、内容类型等轻量分类，不决定剧情结果 |
| 自定义全局判断 LLM 人设 | 附加到判断提示词中的自定义规则；默认提供严格的路由与 JSON 裁判预设 |
| 严禁 LLM 替玩家行动 | 全局约束故事输出不得补写玩家未声明的主动行为 |
| 流式输出 | 请求模型时优先使用流式能力；提供商不支持时保持普通输出 |
| 字数限制 | 选择“展开”后分别设置常规正文、非安全正文、个人信息、环境和心理描述的字数 |
| 玩家不合理行为拒绝话术 | 玩家直接声明结果或越权行动时发送的文本 |
| 全局默认生成超时时长 | 圆桌与 OpenAI 兼容绘图条目填写 `-1` 时使用该值 |
| 缓存自动清理时间 | 按故事最终活跃时间清理存档、状态与生成图片 |
| 图像生成时机 | 多选人物首次登场、首次对话、杀害、侵犯、场景变换和人物战损，默认全选 |

字数按最终可见字符描述给 LLM，只作为生成提示词约束，不会硬截断偶尔超出的内容。默认值依次为常规正文 30 字、非安全正文 200 字、个人信息 120 字、环境 80 字、心理描述 50 字。

开局时，房主和新加入的玩家先收到“环境：”开头的视野所及环境，再收到“自身角色信息＋四项选择”。人物立绘符合所选生成时机时在后台发送。环境提取使用全局判断 LLM，只允许描述玩家当下可以直接看到、听到或感知的内容；不会解释隐藏世界观、剧情、伏笔或视野外 NPC。

## 自定义故事条目

故事条目可以启用多个。使用 `/故事 开始` 且存在可用条目时，玩家先选择已有条目或全随机模式；进入待选状态后可以自然语言回复选择。

- “预期游玩时长”用于圆桌控制剧情节奏，默认 20 分钟。
- 世界观和主角描述允许玩家开局要求覆盖；未填写部分由圆桌补全。
- 必要标签以英文逗号分隔，作为故事底稿的必含要求。
- 内容限制只拼接到实际行动提示词开头，不用于开局角色信息和环境提取；具体数字统一由全局“字数限制”设置。
- 功能机制目前只包含“存档”；未勾选时存读档操作会收到明确提示。
- 长记忆自动压缩在超过配置轮数后保存摘要和最近一轮。
- 群聊多人同游关闭时，该故事不能被其他玩家加入。

## 圆桌会议

至少配置一名常规提案和一名常规评审模型的提供商。新添加的圆桌模型默认启用；显式关闭后不会参与调用。

| 字段 | 行为 |
| --- | --- |
| 身份 | 提案负责提出内容，评审负责综合、修改并形成候选正文 |
| 内容类型 | 常规或非安全；非安全路径缺失时回退常规模型 |
| 优先级 | 按低到高运行，同优先级随机，高优先级模型最后看到更多信息 |
| 常规内容人设提示词 | 选择“常规”时显示并生效，预设侧重短篇叙事、因果、角色一致性与节奏 |
| 非安全内容人设提示词 | 选择“非安全”时显示并生效，使用独立的高强度暴力、血腥和性题材预设 |
| 超时时长 | `-1` 跟随全局，其余正数覆盖全局秒数 |

“轮流讨论”会把前序提案全部提供给后续模型；“单独提案”会并发请求提案模型，再将全部结果提交评审。只有轮流讨论使用“圆桌会议讨论轮数”。

多个评审依次处理，最后一名成功评审的输出为最终正文。所有评审失败时，本次生成失败，不会直接把提案内容发送给玩家。

“生成的内容类型”位于“选择模型提供商”下方。切换类型时只显示对应的人设输入框；两套内容分别保存，来回切换不会覆盖另一套人设。`v0.0.2` 中已自定义的旧版人设会继续生效，用户修改新的对应人设后则以新字段为准。

圆桌模型折叠副标题组合显示“名称——身份——生成的内容类型”，例如“智谱——提案——常规”。故事、OpenAI 兼容、ComfyUI 工作流和自定义节点仍显示各自名称。

## AstrBot 指令与函数工具

插件将 `/故事`、`/存档`、`/读档` 和 `/圆桌会议` 注册为 AstrBot 原生指令，因此可在指令管理页查看和启停。`/故事` 支持开始、加入、继续、结束，以及编号选项或自由行动。

`interactive_fiction` 函数工具只在玩家已有故事或处于待选故事状态时执行。未开局调用会直接返回指令提示，不调用全局判断 LLM；关闭“启用自然语言”时也不会执行操作。

待选故事时，`/故事 [编号/名称/全随机]` 会直接选择故事；进入房间后相同格式用于选项或自由行动。回档移除的玩家仍可通过自然语言收到重新加入提示，并可自然语言重新加入原房间。

## 人物绘图

### OpenAI 兼容

- URL、API Key、模型名称由图像服务实际参数决定。
- 多个 Key 按顺序失败切换。
- 常规内容可使用常规或自由模型；侵犯/杀害相关 CG 只选择自由类型。
- 生图提示词由单独选择的 AstrBot LLM 提供商生成。
- “画风”位于提示词生成模型下方。填写“日系二次元”时，最终提示词会以“日系二次元画风，”开头；已经以“画风”结尾的配置不会重复拼接。
- 画质先尝试 `high`；接口不支持该参数时去掉参数重试。

人物首次生成使用文生图；后续 CG 使用已缓存的角色原图改图，以尽量保持人物一致性。多个可用绘图条目按优先级从高到低失败切换。

故事正文发送后，插件在后台把本轮行动、结果和人物变化交给全局判断 LLM，仅识别已勾选的生图时机。场景变换生成环境全景；人物首次对话和战损使用人物图路径，人物战损提示词会根据伤势表现穿戴品破损、露肤度、表情和姿势。后台任务不占用房间行动锁。

### ComfyUI

工作流内容必须是 ComfyUI 的 API 格式 JSON。服务地址默认 `http://127.0.0.1:8188`。

ComfyUI 条目使用同样的“画风”规则；画风前缀会写入映射到正向提示词节点的最终内容。

每个可用工作流必须至少配置一个正向提示词节点映射；改图工作流还必须配置图像输入节点映射。缺少映射时会切换到下一绘图条目，不会静默执行未注入内容的工作流。

“工作流节点映射条目”通过工作流名称关联节点：

- 节点 ID 指向 API 工作流中的节点。
- 字段路径定位需要替换的字段，例如 `inputs.text`。
- 正向提示词由提示词 LLM 写入。
- 图像输入用于后续 CG 改图，并写入已上传到 ComfyUI 的缓存图像名。

## 推荐首次配置

1. 先只启用一个故事条目、一名常规提案和一名常规评审。
2. 使用轻量模型作为全局判断 LLM。
3. 保持绘图条目关闭，验证开局、行动、结束和普通聊天透传。
4. 再启用存档、多模型轮次、记忆压缩和人物绘图。
