# 配置指南

配置通过 AstrBot 内置插件配置面板管理。模型选择项引用 AstrBot 已配置的 LLM 提供商；插件不会要求在故事条目中重复填写聊天模型凭据。

## 全局设置

| 配置 | 说明 |
| --- | --- |
| 启用自然语言 | 关闭后仅处理明确指令；开启后由全局判断 LLM 区分聊天、插件操作与玩家行动 |
| 全局判断 LLM | 负责消息意图、行动合理性、内容类型等轻量分类，不决定剧情结果 |
| 自定义全局判断 LLM 人设 | 附加到判断提示词中的自定义规则 |
| 严禁 LLM 替玩家行动 | 全局约束故事输出不得补写玩家未声明的主动行为 |
| 流式输出 | 请求模型时优先使用流式能力；提供商不支持时保持普通输出 |
| 玩家不合理行为拒绝话术 | 玩家直接声明结果或越权行动时发送的文本 |
| 全局默认生成超时时长 | 圆桌与 OpenAI 兼容绘图条目填写 `-1` 时使用该值 |
| 缓存自动清理时间 | 按故事最终活跃时间清理存档、状态与生成图片 |

## 自定义故事条目

故事条目可以启用多个。自然语言开局且存在可用条目时，玩家先选择已有条目或全随机模式。

- “预期游玩时长”用于圆桌控制剧情节奏，默认 20 分钟。
- 世界观和主角描述允许玩家开局要求覆盖；未填写部分由圆桌补全。
- 必要标签以英文逗号分隔，作为故事底稿的必含要求。
- 内容限制只拼接到实际行动提示词开头，不用于开局角色信息提取。
- 功能机制目前只包含“存档”；未勾选时存读档操作会收到明确提示。
- 长记忆自动压缩在超过配置轮数后保存摘要和最近一轮。
- 群聊多人同游关闭时，该故事不能被其他玩家加入。

## 圆桌会议

至少启用一名常规提案和一名常规评审模型。

| 字段 | 行为 |
| --- | --- |
| 身份 | 提案负责提出内容，评审负责综合、修改并形成候选正文 |
| 内容类型 | 常规或非安全；非安全路径缺失时回退常规模型 |
| 优先级 | 按低到高运行，同优先级随机，高优先级模型最后看到更多信息 |
| 人设提示词 | 控制该模型的提案或评审风格 |
| 超时时长 | `-1` 跟随全局，其余正数覆盖全局秒数 |

“轮流讨论”会把前序提案全部提供给后续模型；“单独提案”会并发请求提案模型，再将全部结果提交评审。只有轮流讨论使用“圆桌会议讨论轮数”。

多个评审依次处理，最后一名成功评审的输出为最终正文。所有评审失败时，本次生成失败，不会直接把提案内容发送给玩家。

## 人物绘图

### OpenAI 兼容

- URL、API Key、模型名称由图像服务实际参数决定。
- 多个 Key 按顺序失败切换。
- 常规内容可使用常规或自由模型；侵犯/杀害相关 CG 只选择自由类型。
- 生图提示词由单独选择的 AstrBot LLM 提供商生成。
- 画质先尝试 `high`；接口不支持该参数时去掉参数重试。

### ComfyUI

工作流内容必须是 ComfyUI 的 API 格式 JSON。服务地址默认 `http://127.0.0.1:8188`。

“工作流节点映射条目”通过工作流名称关联节点：

- 节点 ID 指向 API 工作流中的节点。
- 字段路径定位需要替换的字段，例如 `inputs.text`。
- 正向提示词由提示词 LLM 写入。
- 图像输入用于后续 CG 改图，并写入已上传到 ComfyUI 的缓存图像名。

## 推荐首次配置

1. 先只启用一个故事条目、一名常规提案和一名常规评审。
2. 使用轻量模型作为全局判断 LLM。
3. 保持绘图条目关闭，验证开局、行动、结束和普通聊天透传。
4. 再启用存档、多模型轮次、记忆压缩和人物绘图。
